第一階段：網路與 DNS 基礎

Lesson 1. 網站是如何在手機上出現的？

💡 核心技術科普觀念

使用者在手機輸入網址後，瀏覽器會向遠端伺服器發送 HTTP 請求（Request），伺服器收到後處理並回傳網頁檔案（HTML/CSS/JavaScript），最後手機瀏覽器將這些程式碼渲染成我們看到的漂亮畫面。這中間任何一個環節卡住或距離太遠，使用者就會感覺到『慢』。

💥 客戶痛點與常見危機

網頁載入時間超過 3 秒，導致高達 40% 的使用者直接關閉視窗流失；且伺服器如果單獨面對全球使用者的連線，頻寬與運算資源會瞬間被吃光而宕機。

🛡️ 騰雲架構優勢與話術利基

騰雲運算在最前線佈建了高效能節點，縮短傳輸物理距離，讓請求不需要每次都大老遠跑回客戶的源站主機，從根本上解決連線延遲問題。

📊 運作架構示意圖

📱 手機瀏覽器 發送 HTTP 請求 ➡️ 🖥️ 伺服器
📱 渲染畫面 ⬅️ 回傳 HTML/CSS/JS 🖥️ 處理完成
傳輸距離越遠、節點越多，網頁打開就越慢。

業務實戰殺手級金句 (Sales Pitch)

「客戶的注意力只有 3 秒。網頁每多慢 1 秒，您的轉單率就直接下滑 10%。我們的服務就是幫您把這 3 秒黃金時間牢牢抓著！」

Lesson 2. 什麼是 DNS？

💡 核心技術科普觀念

DNS（Domain Name System）是網路世界的網域解析系統，功能就像是『網路世界的電話簿或導航系統』。電腦只認識 IP 位址（例如 1.1.1.1），而人類只記得住網址（例如 www.skycloud.com.tw）。DNS 的任務就是把人類輸入的網址，精確翻譯成電腦懂的 IP 數字。

💥 客戶痛點與常見危機

如果客戶的網域解析速度慢，使用者輸入網址後會卡在白畫面好幾秒，誤以為網站掛了；如果 DNS 伺服器不穩定或遭受攻擊斷線，全天下的客人都會找不到路，網站直接形同蒸發。

🛡️ 騰雲架構優勢與話術利基

我們提供高可用性、全球分佈式的頂級 DNS 解析服務，解析時間縮短至毫秒級，確保任何時候客人都查得到路、進得來店面。

⬇️ [ DNS 核心解析 ] ⬇️
轉換成電腦 IP: 211.23.XX.XX

Lesson 3. 為什麼 DNS 對客戶的生意很重要？

💡 核心技術科普觀念

DNS 不僅關乎『找不找得到路』，更直接決定了『安全與第一印象』。現代企業會啟用 DNSSEC（網域系統安全擴充），為 DNS 查詢資料加上數位簽章，防止駭客在路上攔截並竄改解析結果（意即 DNS 劫持）。

💥 客戶痛點與常見危機

駭客利用 DNS 漏洞將您的忠實客戶導向一個長得一模一樣的假釣魚網站，騙取信用卡的密碼。一夕之間，客戶對您的企業品牌信任度歸零，甚至面臨法律訴訟。

🛡️ 騰雲架構優勢與話術利基

騰雲運算原生支援頂級 DNSSEC 安全機制與優化演算法，大幅調降首位元時間（TTFB），兼顧『極致速度』與『絕對安全』。

Lesson 4. 進階流量調度：什麼是 GTM？

💡 核心技術科普觀念

GTM（Global Traffic Manager，全球流量管理器）是建構在 DNS 之上的高級大腦。它不只給出一個固定的 IP，而是會即時動態監測全世界各個伺服器的健康狀態、當前流量，並根據使用者的地理位置，給予最合適、最快的路徑。這是一種高級的自動化流量分流與備援技術。

💥 客戶痛點與常見危機

單一主機遭遇斷線、或者某條網路線路（如中華電信）突然塞車，導致特定地區的使用者完全打不開網站，業務瞬間停擺。

🛡️ 騰雲架構優勢與話術利基

我們的 SkyGTM 系統是智慧型的交通警察。一旦偵測到 A 機房故障，在毫秒內就會把後續所有流量自動切換到備用的 B 機房，對終端使用者而言完全無感。

Lesson 5. 什麼是 CDN？

💡 核心技術科普觀念

CDN（Content Delivery Network，內容傳遞網路）是一種透過在全世界部署數百、數千台快取伺服器（節點）所組成的網路系統。它的核心邏輯是：把客戶網站上的靜態檔案（如圖片、影片、活動樣式）複製一份，提前發送到離使用者最近的邊緣節點上，實現地緣上的就近存取。

💥 客戶痛點與常見危機

如果主機在台北，美國或東南亞的客戶要下載一張產品圖，數據得橫跨太平洋，速度極慢；若遇到熱門檔期，上萬人同時跟台北主機要資料，主機頻寬直接被撐爆而癱瘓。

🛡️ 騰雲架構優勢與話術利基

騰雲運算擁有全球佈建的頂級 CDN 網路，能將客戶的產品內容瞬間發佈到離消費者最近的前線節點，實現全網秒開的流暢體驗。

📊 運作架構示意圖

無 CDN：全球使用者 ➡️ 瘋狂擠爆單一源站 (太遠且易崩潰)
有 CDN：使用者 ➡️ 鄰近 CDN 邊緣節點 (極速回傳) ➡️ 僅必要時回源

Lesson 6. 靜態快取 vs. 動態加速

💡 核心技術科普觀念

CDN 的加速手段分為兩種。第一種是『靜態快取』，針對不會變動的內容（圖片、CSS、JS、HTML檔），直接在 CDN 節點落地儲存，重複利用；第二種是『動態加速』，針對會變動的內容（購物車結帳、API數據、個人化資料），無法快取，但 CDN 透過自建的優化骨幹網路與智慧路由，以走『高鐵專線』的方式用最快速度傳回源站主機。

💥 客戶痛點與常見危機

電商平台在限時搶購時，網頁外觀圖片跑不出來，而購物車按鈕點擊後因為路由塞車遲遲沒有回應，導致訂單結帳失敗、客戶狂刷退單。

🛡️ 騰雲架構優勢與話術利基

我們的解決方案既能在最外圍大量消化 90% 以上的靜態圖片請求，又能透過優化路由為動態 API 加速，兼顧了速度與交易的即時準確性。

📊 運作架構示意圖

📷 靜態快取： 圖片/影片/CSS ➡️ 留在邊緣節點直接回傳 (命中)
⚡ 動態加速： 購物車/API ➡️ 智慧最優路由 ➡️ 專線衝回源站處理

業務實戰殺手級金句 (Sales Pitch)

Lesson 7. 節點 (Edge) 與回源 (Origin) 之間的關係

💡 核心技術科普觀念

在 CDN 架構中，『邊緣節點（Edge）』是站在最前線服務客戶的服務生，而客戶的自有主機則被稱為『源站（Origin）』。當 Edge 節點沒有該檔案的快取時，它必須向 Origin 源站詢問並要一份過來，這個動作稱為『回源（Fetch/Origin）』。如果源站當機、或者源站反應太慢導致 Edge 等不到回應，前端就會跳出著名的 502 Bad Gateway 或 504 Gateway Timeout 錯誤碼。

💥 客戶痛點與常見危機

活動一開跑，CDN 的命中率沒調好，導致成千上萬的流量在同一秒全部衝回源站（稱為快取雪崩），直接把客戶的源站主機壓垮，網站全面癱瘓癱死。

🛡️ 騰雲架構優勢與話術利基

騰雲運算的專業技術團隊（FAE）具備深厚的架構調校經驗，能精準設定快取過期時間與回源控制，幫客戶擋下前線 95% 以上的敲門流量，保護後方源站安全。

➡️
🌐 CDN 邊緣節點
沒資料時 (回源)
➡️
🖥️ 客戶源站 (Origin)
若崩潰 ➡️ 報 502/504

Lesson 8. 關鍵效能指標（Cache Hit Ratio & Latency）

💡 核心技術科普觀念

評估一個 CDN 系統到底有沒有發揮實質功效，技術與商業上有兩個絕對指標：第一、快取命中率（Cache Hit Ratio）：前線節點直接回傳檔案給用戶的比例，理想狀態在 85% ~ 95% 以上。第二、延遲時間（Latency）：數據從發出到收到的往返時間（通常看 TTFB）。這兩個指標直接決定了使用者的流暢度與源站的頻寬節省量。

💥 客戶痛點與常見危機

很多企業買了便宜的 CDN，但因為沒有技術團隊幫忙維護優化，快取命中率只有 20%，結果既要付 CDN 頻寬費、又要付源站爆量頻寬費，形同花兩次冤枉錢。

🛡️ 騰雲架構優勢與話術利基

我們提供透明化、秒級更新的『報告大本營』與圖表分析系統，讓業務能直接拿著數據向客戶證實：騰雲幫他們做到了超高命中率與極低延遲，省下了大筆主機頻寬費。

Lesson 9. 拆解我們的 CDN 引擎：反向代理與 Nginx

💡 核心技術科普觀念

騰雲運算的 CDN 系統之所以強大，在於底層極其扎實且充滿彈性的技術選擇。我們的每一個 CDN 邊緣節點，在底層架構上，都是一台經過深度效能優化、高併發調校的獨立『反向代理 Nginx 伺服器』。Nginx 負責接收第一線的所有網路流量，並扮演最前線過濾惡意請求、快取靜態資源的強大核心引擎。

💥 客戶痛點與常見危機

市面上許多封閉式的 CDN 平台規則僵硬，客戶如果有一些特殊的 HTTP Header 檢查、或是非標準的快取邏輯需求，跨國大廠根本不願意或無法為了單一客戶進行底層程式碼改寫與客製。

🛡️ 騰雲架構優勢與話術利基

因為我們的底層完全基於強大且可高度程式化的 Nginx 反代架構，不論客戶的商業邏輯多麼複雜，我們的技術工程師（FAE）都能在幾分鐘內為其撰寫專屬的 Nginx Rule 規則，實現秒級別的彈性客製化。

Lesson 10. 站點 (Site) 與節點 (Node) 的多對多宇宙

💡 核心技術科普觀念

在騰雲的系統設計中，『站點（Site）』代表客戶所管理的網站域名配置（例如 customer.com），而『節點（Node）』代表分散在全球、實體執行反向代理的 Nginx 伺服器實例。在底層數據庫與系統關聯上，我們支援極具彈性的『多對多關聯架構』——意即多個節點可以共同為同一個站點提供服務，而一個節點同時也可以掛載多個不同的站點。這種高度靈活的架構，賦予了我們在面臨大流量衝擊時，隨時動態抽調、增派、重組硬體資源的恐怖實力。

💥 客戶痛點與常見危機

大部分中小型 CDN 廠商的架構屬於死板的一對一或硬性分組，當某個客戶遭受超大型網路突發流量時，系統無法跨組靈活動態調度其他閒置的 Nginx 伺服器前來支援，只能眼睜睜看著伺服器爆滿。

🛡️ 騰雲架構優勢與話術利基

我們的管理控制台內建靈活的多對多宇宙調度能力。一旦市場發生突發大流量，系統調度大腦可以一鍵將數十台閒置的 Nginx 獨立節點瞬間關聯到該客戶的站點上，形成堅不可摧的防禦火網。

Lesson 11. 為什麼我們要推「獨立站點」？

💡 核心技術科普觀念

雖然騰雲的底層技術支援多對多的共用關聯，但在實際商業推廣與架構部署上，我們對核心客戶主要推行『獨立站點（Isolated Site）』策略。這意味著：我們會為大客戶配置一組或多台『完全專屬、與他人隔離』的 Nginx 獨立反向代理節點。這些 Nginx 節點不掛載任何其他客人的網站，百分之百的 CPU、記憶體與網路頻寬，全部只為該客戶這一個站點服務。

在傳統大眾型共用 CDN 中，幾百個網站共用同一台節點。如果隔壁鄰居網站得罪了駭客、遭遇了毀滅性的 DDoS 流量攻擊，整台 Nginx 伺服器會瞬間被塞爆或當機，導致同在一台伺服器上的『無辜鄰居（您的網站）』也跟著連帶斷線、無端受害（此現象稱為鄰居效應 / Neighbor Effect）。

🛡️ 騰雲架構優勢與話術利基

Lesson 13. 網路攻擊百百種（DDoS & 惡意爬蟲）

💡 核心技術科普觀念

Lesson 14. 網站專屬守衛：WAF 是什麼？

💡 核心技術科普觀念

WAF（Web Application Firewall，網頁應用程式防火牆）是專門防禦 HTTP/HTTPS 網頁層級（網路第七層）的高級守衛。傳統的防火牆（Layer 4）只看連線 IP 是誰、有沒有允許，但完全看不懂網頁內容。而 WAF 就像是精通語言的安檢官，能深度檢查 HTTP 請求內容裡有沒有藏著 SQL 注入（惡意偷拔資料庫）、XSS 跨網站指令碼（植入木馬）或惡意漏洞利用程式碼。

💥 客戶痛點與常見危機

雖然網站買了傳統防火牆，但駭客偽裝成正常瀏覽用戶，直接在網站搜尋框或登入欄位輸入一串惡意資料庫語法（SQL 注入），一秒把客戶後台的幾十萬筆會員個資、信用卡號全部打包帶走（脫褲），引發災難性商譽危機。

🛡️ 騰雲架構優勢與話術利基

我們在專屬的 Nginx 節點上直接深度整合了高效能 WAF 規則引擎，在最外圍、最前線就將所有試圖鑽代碼漏洞的惡意請求直接拍死在沙灘上，保護後台應用程式與資料庫安全。

Lesson 15. HTTPS 與 SSL/TLS

💡 核心技術科普觀念

HTTPS 是指在網站傳輸過程中加入了 SSL/TLS 加密協定。當用戶在網頁上輸入帳號密碼、信用卡時，這些資料會被轉換成一串連神仙都看不懂的亂碼進行傳輸，防止在經過各個網路節點時被中途截聽。同時，HTTPS 會在瀏覽器網址列顯示一個代表安全的『綠色鎖頭』，這是當今所有現代網站的必備標配，也是 Google 搜尋排名（SEO）的重要加分項。

💥 客戶痛點與常見危機

網站沒有啟用 HTTPS，導致用戶刷卡時卡號被惡意第三方竊聽盜刷；或者企業內部的 IT 人員忘記手動更新 SSL 安全憑證，導致某天客戶一打開網站直接跳出驚悚的『此網站不安全、隱私權可能外洩』紅色警告，客戶當場嚇跑，業績暴跌。

🛡️ 騰雲架構優勢與話術利基

騰雲運算的 CDN 系統直接在 Nginx 前線邊緣節點提供自動化的 SSL 憑證申辦、無縫掛載與過期自動續約服務（預設一鍵啟用），客戶的工程師不需要每年提心吊膽擔心憑證過期。

Lesson 16. 網頁前端防護機制（點擊劫持與安全標頭）

💡 核心技術科普觀念

『點擊劫持（Clickjacking）』是一種極具欺騙性的前端網頁駭客攻擊。駭客會在一個惡意網站上，利用 CSS 將客戶的正牌網站包在一個完全透明的 iframe 框架裡，並疊加在一個看似無害的按鈕（例如：『點此領取免費貼圖』）上方。使用者以為自己點的是貼圖，但實際上卻是點擊了正牌網站內部的『確認付款』或『刪除帳號』按鈕。防禦這種攻擊的最佳手段，就是在 Nginx 伺服器回傳網頁時，強制加上一組名為 X-Frame-Options 或 Content-Security-Policy 的 HTTP 安全標頭（Security Headers），嚴格限制網頁不可以被其他人任意內嵌。

💥 客戶痛點與常見危機

客戶的網站雖然寫得很安全，但因為缺乏伺服器端的前端防護安全標頭配置，被詐騙集團拿去套殼、內嵌做成點擊劫持陷阱，導致大量消費者受騙上當，客戶最後怪罪並起訴正牌企業，商譽重創。

🛡️ 騰雲架構優勢與話術利基

這正是我們技術能力的展現。我們的 FAE 能直接在邊緣節點的 Nginx 配置中一行程式碼搞定安全標頭，不需要客戶大費周章去修改他們脆弱的舊網站原始碼，直接在最外圍套上前端安全金鐘罩。

Lesson 23. POC (概念驗證) 的完美引導與 FAE 分工

💥 客戶痛點與常見危機

業務為了拿單，在沒問過工程師的情況下，在客戶面前拍胸脯亂答應：『我們的系統連一毫秒都不會延遲、什麼瘋狂的功能我們都能隔天寫出來！』導致後續 FAE 介入時發現技術根本辦不到，客戶怒斥欺騙，企業商譽嚴重受損。
